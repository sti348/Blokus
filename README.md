# 角斗士棋（BlockTurf）

网页版角斗士棋（英文名 BlockTurf）：**方块**、**三角块**、**宝石阵（Gemblo）**，以及原创的**立体（三维）**和**三棱柱**玩法，支持 **1–6 名玩家同屏对战**（宝石阵最多 6 方，其他棋盘最多 4 方）或**联机对战**，座位可以交给三档难度的**电脑**，也可以接入你自己的**大模型**（OpenAI 兼容接口）。界面有 10 种语言，每种棋盘第一次进入时有新手引导。纯 HTML / CSS / JavaScript，没有第三方依赖，也不需要构建。

## 开始游戏

- **只在本机玩**：直接用浏览器打开 `index.html`（离线可用，只有标题字体需要联网加载）。
- **要联机**：在项目目录运行

  ```bash
  node server.js          # 或 npm start；默认端口 8080，可用 PORT=3000 node server.js 修改
  ```

  然后打开 `http://localhost:8080`。终端会打印本机的局域网地址，同一网络里的朋友用这个地址打开即可。把服务器部署到公网，就能和外地朋友联机。
  用 `LLM_PROXY=1 node server.js` 启动时，服务器还会替网页转发大模型请求（见下文「大模型电脑」）。

## 棋盘与模式

| 模式 | 棋盘 | 棋子 | 参战方 |
| --- | --- | --- | --- |
| 标准 | 20×20 方格 | 21 块方块（1–5 格，共 89 格） | 2–4 方，各自从一个角出发 |
| 双人 | 14×14 方格 | 同上 | 2 方，起点在 (5,5) 与 (10,10) |
| 三角块 | 六边形三角格 | 22 块三角块（1–6 格，共 110 格） | 2–4 方，6 个公共起点 |
| 宝石阵 | 原版六边形格棋盘（505 格） | 18 块六边形拼块（1–5 格，共 72 格） | 3、4、6 方，起点在角上 |
| 立体 | 7×7 地面、限高 5 层 | 12 块立方体（1–4 块，共 41 块） | 2–4 方，各自从地面的一个角出发 |
| 三棱柱 | 六边形三角格地面、堆叠成层 | 19 块三棱柱棋子（1–4 格，共 66 格） | 2–4 方，各自从六边形的一个角出发 |

三角块棋盘的边长随人数变化：4 人为 9（486 格），3 人为 8，2 人为 7。三角块可以旋转 6 个方向并翻转；第一块盖住任意一个空着的起点即可。

### 宝石阵（Gemblo，按原版规则）

按 [Gemblo 官方规则](https://www.ultraboardgames.com/gemblo/game-rules.php)（规则书的文字和插图）复刻：

- **棋盘**：平顶六边形格子组成的大六边形，共 505 格（按规则书图 1、图 2 数格子还原：中心落在外接半径 22 格的大六边形内的格子）。6 方用整块棋盘，起点在 6 个角；4 方只用中间的“方形”区域（295 格，19 列），起点是它的 4 个角（图中的 F）；3 方用中间外接半径 15 的六边形区域（241 格），起点在它相间的 3 个角（图中的红箭头）。
- **规则**：第一块盖住自己的起点。同色的棋子不能接触；之后每块都要和自己的某块棋子**尖对尖**，相隔正好一条边的距离。隔开的那条边若两边是别人的**同一块**棋子，就算被挡住；落在别人两块棋子的交界处则可以（规则书图 9、图 10）。
- **计分**：所有人都放不下时结束，只数没放上棋盘的格子，剩得最少的获胜，没有奖励分。
- **人数**：3、4、6 方。两人对战时每人各执两色（4 方区域），在座位里把两个颜色都设为自己；5 方需要额外摆障碍棋子，暂不支持。
- **棋子**：每人 18 块，与原版一致：单格 1、双格 1、三格 3（直三、弯三、三角）、四格 5（直四、拱形、波浪、菱形、三叉）、五格 8（直五、台阶、大拐、尖角、长浪、S 形、风车、长叉）。形状按原版实物照片逐块核对，并和规则书图 2（五人局把一种颜色的 15 块摆成障碍）对过，定义在 `js/pieces.js` 的 `GEMBLO_RAW` 里。
- 颜色按原版六色：蓝、黄、红、绿、紫、橙。

### 立体模式（原创规则）

立体模式没有现成规则可循，这里的玩法是为三维空间专门设计的：

1. **重力落子**：选好棋子和朝向后指向地面上的一列，棋子从上方竖直落下，停在地面或任何人的棋子上；不能悬空，也不能超过 5 层的限高。这样在平面屏幕上也能准确落子。
2. **棱角相接**：每块新棋子必须和自己已有的棋子**共享一条棱或一个顶点**，但**不能面贴面**。因此不能直接叠在自己的棋子正上方。
3. **借道攀登**：可以叠在别人的棋子上。被对手的“墙”挡住时，可以爬到它上面继续扩张；反过来也能压住对手往上长的角。
4. **棋子**：所有 1–4 块的多立方体，共 12 块。只能在三维中旋转（24 个朝向），不能镜像，所以互为镜像的“左旋”“右旋”是两块不同的棋子。
5. **棋盘大小**：4 人 7×7、3 人 6×6、2 人 5×5，高度都是 5 层。尺寸由自对弈调出：普通难度的电脑平均剩下 4–6 块方块，和标准盘的紧张程度相近。

名次与其他模式相同：手里剩下的方块越少越靠前，全部放完的排最前，最后一块是单块的更靠前。操作：R 水平转，F 向前翻，G 侧翻，Q / E 或棋盘左上角的按钮转视角，拖动空白处（或右键拖动）自由旋转视角。

**透视**，用来看清被挡住的结构：

- **透视**（`X` 键或眼睛按钮，每局默认关闭）：别人的方块变成半透明，挡在待放棋子前面的更淡，能看到内部的空腔和别人藏在里面的角；**自己的方块保持不透明**，一眼分清哪些是自己的。
- **切层**（`[` / `]` 或滑块）：只显示下面几层，上面的楼层只留淡淡的影子。

### 三棱柱模式（原创规则）

三角块的立体版：六边形地面由三角形组成，每一格竖起来是一个三棱柱，规则沿用立体模式。

1. **重力落子、棱角相接**：和立体模式一样，棋子从上方落下，停在地面或任何棋子上；自己的棋子之间不能**面贴面**（侧面的长方形、上下的三角形都算面），必须共享一条棱或一个顶点。三棱柱的相邻关系更密：一格有 5 个面邻居，却有多达 33 个棱角邻居，可走的路线比立方体多得多。
2. **棋子**：所有 1–4 格的多棱柱，共 19 块（1 + 2 + 3 + 13）。可以绕竖轴每次转 60°（`R`），也可以上下翻转（`F`），共 12 种转法；不能镜像。
3. **起点**：四个座位对应六边形的四个角（左上、右上、右下、左下），第一块要压住地面上自己角上的起始格。
4. **棋盘大小**：4 人边长 4、高 4 层，3 人边长 3、高 6 层，2 人边长 3、高 5 层。尺寸由自对弈调出：普通难度的电脑平均剩下 3–6 格，困难对普通 21 胜 3 负，普通对简单 23 胜 1 负。

透视、切层和视角操作与立体模式相同。

参战人数：宝石阵可选 **3、4、6 方**，其他棋盘人数固定（标准、三角块、立体、三棱柱 4 方，双人 2 方）。每个座位设为 **玩家** 或 **电脑**（电脑在同一行选难度，大模型再选配置，旁边的齿轮打开大模型设置）。快速开局按人数给出：1 / 2 / 3 个玩家加电脑、全是玩家同屏、电脑观战。棋盘用 3×2 的卡片选择（带图标，选中的卡片有滑动的高亮）。左边的电脑演示局下的就是选中的棋盘和人数，下面写着棋盘名和简介。对局记录、玩法规则、音效、深色主题和语言在面板右上角的图标里。

## 规则

- 按 **蓝 → 黄 → 红 → 绿** 轮流落子，第一块必须盖住起点。
- 之后每块都必须与自己的棋子**角对角**相接（只共享一个顶点），且自己的棋子之间**不能边贴边**；与别人的棋子边贴边没关系。
- 无处可放的玩家自动出局，所有人都放不下时对局结束。
- 名次：手里剩下的格子越少越靠前；全部放完的排最前，最后一块是单格的更靠前（等同于官方计分：每个未放置的格子 −1，全部放完 +15，单格收尾再 +5）。
- 界面上不显示分数：玩家卡片显示每人**还剩几块**，结算表显示剩余的块数和格数。

## 联机

1. 一人在「联机对战」里点 **创建房间**，得到 5 位房间号。
2. 朋友在「联机对战」里输入房间号加入，并自动入座。
3. 房主在房间里换棋盘（宝石阵可选人数）、安排座位（玩家 / 电脑、电脑难度）、换棋盘、设电脑速度，人齐后开始。
4. 当前玩家拿起棋子挪动、旋转时，其他人会在自己的棋盘上实时看到这块棋子的虚线轮廓，回合栏也会显示“正在尝试摆放”。这只是实时转发，不会写进对局记录。
5. 对局中每一步都由规则引擎校验。玩家掉线时，房主可以把他的座位 **交给电脑**；房主掉线约 10 秒后，在线玩家中的一位自动接任房主。终局后房主可以 **再来一局**。

联机有两种运行方式，界面和规则完全相同：

- **自建服务器**（`server.js`）：浏览器通过 SSE 接收房间状态、通过 POST 发送操作；服务器校验每一步并执行电脑的回合。房间保存在内存中，没人连接 30 分钟后自动清除。
- **在 Claude 发布的页面中打开**：页面用自带的共享存储保存房间、用在线状态判断谁在线，电脑回合由房主的浏览器执行。朋友需要能打开该页面，并有“可编辑”或“参与者”权限。

服务器接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/info` | 探测服务器 |
| GET | `/api/stats` | 全站游玩次数 `{ plays }` |
| POST | `/api/stats/play` | 新开一局，次数 +1（同一地址 3 秒内只算一次） |
| POST | `/api/rooms` | 建房 `{ token, name, mode }` → `{ code }` |
| GET | `/api/rooms/:code` | 房间是否存在 |
| GET | `/api/rooms/:code/stream?token=` | SSE：`hello` / `room` / `peers` 事件 |
| POST | `/api/rooms/:code/op` | 房间操作 `{ token, op }` |
| POST | `/api/rooms/:code/preview` | 当前玩家正在尝试的位置 `{ token, preview }`，只转发不保存 |
| POST | `/api/llm` | 大模型转发 `{ url, key, body }`，只转发到 `…/chat/completions`、`…/systemone`、`…/decisions`；需用 `LLM_PROXY=1` 开启 |

`token` 是每个浏览器为每个房间生成的随机串，服务器只公开它的哈希，别人无法冒充你落子。

## 操作

| 操作 | 电脑 | 手机 / 平板 |
| --- | --- | --- |
| 选棋子 | 点击右侧托盘 | 点击下方托盘 |
| 移动 | 鼠标移到棋盘上，或方向键 | 在棋盘上点击 / 拖动 |
| 旋转 | `R`（`Shift+R` / `E` 逆时针）、右键、滚轮 | 旋转按钮 |
| 翻转 | `F`、鼠标中键 | 翻转按钮 |
| 放置 | 左键单击、回车 | 再点一次同一格，或按“放置” |
| 提示 / 悔棋 | `H` / `Ctrl+Z`（悔棋仅限本地对战） | 顶部按钮 |

**每位玩家的剩余棋子**显示在各自的玩家卡片上（已用的变淡）；点一下卡片，右侧托盘会放大显示那位玩家的棋子，点“看自己的”返回。

**动画**：落子时整块棋子从略微抬起的位置落到棋盘上，轻轻一压后亮一下，轮到自己时可落子的角点淡入；换人时回合栏闪一下，剩余块数减少时数字跳一下；进入对局时棋盘、玩家卡片和托盘依次出现；结算表逐行出现，自己获胜时撒彩纸。系统开启“减少动态效果”时全部关闭。

其他功能：可落子角点提示、当前没有位置的棋子以虚线标出、中途“停手”、本地对局自动保存（返回菜单后可“继续上局”）、音效开关。

**主题**：默认浅色，不跟随系统；在开局页面右上角或对局顶栏点月亮按钮切换，设置保存在本机。

**开局页面**：每次打开网站默认是标准棋盘（本次访问里切换过的棋盘会保留到下次刷新前）。右下角显示全站累计游玩次数（只在首页显示）：用自建服务器时由服务器累计并保存在 `stats.json`（可用 `STATS_FILE` 指定位置）；在 Claude 发布的页面里，每位访客在共享存储里记自己的次数，首页显示所有人之和（只看权限的访客不能写，不计入）；直接打开本地文件时不显示。每新开一局算一次，联机由房主记，接着上局和回放不算。电脑上一屏放得下（1366×768 的屏幕也不用滚动），切换本地 / 联机、快速开局、人数和座位时，只有该变的内容变化，其他位置不动。页面上的文字不能拖动或长按选中（输入框除外）。

## 对局记录

- **保存 / 导出**：对局结束时，结果窗口里可以「保存到本机」（浏览器里最多 60 局）或「导出文件」（`blockturf-<模式>-<日期>.json`）。关掉结果窗口后，顶栏的「结果」按钮可以再打开它。本地和联机对局都可以。
- **对局记录**：开局页面的「对局记录」列出保存过的对局（棋盘、时间、玩家、手数、胜者），可以回放、导出、删除，也可以导入导出过的文件。
- **回放**：右侧换成回放面板，可以播放 / 暂停（四档速度）、逐步前进后退（`←` `→`，`Home` / `End`）、拖动进度条，或在下棋流程列表里点任意一步跳过去；立体模式照常转视角、透视、切层。回放时不能落子。
- **文件内容**：`players`（座位、名字、电脑难度）和 `actions`（每一步的棋子、朝向、位置，大模型的理由）用于回放；`moves` 是可读的下棋流程（第几手、谁、哪块棋子、占了哪些格子，以及停手、无处可放、对局结束），`result` 是名次和剩余块数。导入时只读座位和动作，配置按座位重新生成、每一步重新校验，文件被改过也只会在第一步不合法处截断。

## 多语言

- 界面支持 10 种语言：English、简体中文、繁體中文、日本語、한국어、Español、Français、Deutsch、Português、Русский。**默认英文**，第一次打开时按浏览器的语言偏好自动选择（`zh-TW`、`zh-HK`、`zh-Hant` 用繁体，其余中文用简体；都不支持时用英文）。
- 开局页面右上角的地球图标可以手动切换，选过之后记在本机。
- 游戏名：中文界面叫“角斗士棋”（繁体“角鬥士棋”），其他语言叫 **BlockTurf**。
- 电脑、“你”“玩家2”这类默认名字按当前语言显示；大模型写在玩家卡片上的理由也按界面语言回答。导出的对局记录里，可读的下棋流程用导出时的语言。
- 词典在 `js/i18n/<语言>.js`，英文 `en.js` 是全部词条的清单。加一种语言：在 `js/i18n.js` 的 `LANGS` 里登记、复制一份 `en.js` 翻译、在 `index.html` 里引入；测试会检查每种语言的词条是否齐全、占位符和 HTML 标签是否与英文一致、复数形式是否够用。

## 新手引导

- 每种棋盘（标准、双人、三角块、宝石阵、立体、三棱柱）第一次进入对局时自动弹出，共 6 步：怎样获胜、第一块放哪、怎样连接（附示意图：哪种接法可以、哪种不行）、怎样放棋子（立体模式讲落子和转视角，触屏另有说明）、玩家卡片、哪里能再看。
- 引导时会把要讲的区域圈出来，其他地方变暗；本地对局里电脑会等引导结束再走。
- 可以随时“跳过”（或按 Esc），用 ← → 翻页；看完或跳过后记在本机，同一种棋盘不再自动弹出。对局顶栏的 **?** 按钮可以再看一遍。

## 电脑难度

- **简单**：随机落子，偏向大块棋子。
- **普通**：贪心估值，考虑棋子大小、新增角点、占掉对手的角点、开局向中心扩张。
- **困难**：先用贪心筛出候选，再模拟落子，比较自己与对手剩余的可行步数和还能放下的棋子；对手越少，越重视压制对手。
- **大师**：在困难电脑的 8 个候选里，每步都往后推演两轮（所有人按贪心选法、带一点随机），推演 4 次取平均，再结合困难电脑的估值选最好的。每步几十到几百毫秒，分段计算，不卡界面。
- **大模型**：由你接入的大模型来下，棋力来自大师的搜索，见下一节。

自对弈测试中，困难明显强于普通、普通远强于简单。大师和三个困难电脑对局时，各棋盘的胜率（括号里是困难电脑在同样条件下的胜率）：标准 41%（29%，共 384 局，平均剩 11.7 格，对手 15.6 格）、双人 75%（58%）、立体 44%（25%）、三角块 40%（27%）、三棱柱 33%（23%）；四人局公平胜率是 25%。

## 大模型电脑

把电脑难度设为 **大模型**，在开局页面（或联机房间）的「大模型设置…」里选模型来源并填写，可以先点「测试连接」。设置和密钥只保存在这台设备的浏览器里，只会发送给你填写的地址。

**OpenAI 兼容接口**：任何 Chat Completions 格式的接口，地址填到 `/v1` 为止，例如 `https://api.deepseek.com/v1`、`https://api.openai.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1`、`https://openrouter.ai/api/v1`、本地 Ollama 的 `http://localhost:11434/v1`；本地模型的密钥可以留空。

- 「关闭深度思考」默认打开：DeepSeek、智谱、通义千问的接口会自动带上关闭思考的参数（DeepSeek V4 默认会先长时间思考，关掉后一步只要几秒）。接口不认这个参数时自动去掉重试。测试连接时如果发现模型还在深度思考，会提醒你。

**Jev（TypeSafe）**：Jev 是决策模型，不写文字，而是回答一道选择题：从候选里选一步并给出把握，通常不到一秒。可以用 TypeSafe 官方接口（`https://api.typesafe.ai/v1`，模型 `jev-latest`），也可以用 OpenRouter（地址 `https://openrouter.ai/api/v1`，模型 `~typesafe/jev-latest`，会自动使用 OpenRouter 的 Decisions 接口 `/api/alpha/decisions`）；设置框里有一键填入的按钮。

**每个颜色可以用不同的模型**：设置框里可以建多个配置（各自起名，例如“DeepSeek”“Jev”），座位难度选「大模型」后在旁边选用哪个配置。联机时房间里只记配置的名字，由房主那台设备上同名的配置来调用（找不到同名的就用第一个）。

**怎么下棋**（为什么不直接让模型下）：大模型算不清这种棋的空间组合，直接让它挑棋会输给程序。所以棋力来自搜索，模型只做取舍：

1. 大师电脑先把候选各推演两轮，只把推演结果差不多一样好的几步（和最好一步相差不超过 0.6，最多 4 步）交给模型。只有一步明显最好时直接走，不问模型（大约一半的回合）。
2. 交给模型的是局面（棋盘图、各方得分和剩余、谁在领先）和这几步的特征（落子后自己和对手的走法变化、分别压住哪家对手的角点），让它做战略取舍，比如压制领先者、抢空地。理由（Jev 是把握）显示在玩家卡片上。
3. 出错、超时（默认 30 秒）或回答里没有有效选项时，这一步由大师代下，并提示原因。等待时状态栏会显示已经等了几秒。

范围是用自对弈定的：如果模型每次都故意选这几步里最差的一步，成绩仍接近大师（标准棋盘平均名次 2.19，大师约 2.0，困难 2.38）；以前给模型 12 个候选随便选时是 3.17。所以模型怎么选都在大师水平附近，选得好时还能更强。

**跨域**：网页直接调用接口时，需要接口允许跨域访问（CORS）。如果“测试连接”提示连不上，可以用 `LLM_PROXY=1 node server.js` 启动服务器并从服务器地址打开页面，直连失败时会自动改由服务器转发。转发默认关闭：开启后，能访问这台服务器的人都可以借它向任意地址发请求，只应在自己信任的网络里开。

**联机**：大模型电脑由房主（房主离线时由在线玩家中的一位）的浏览器用自己的设置调用模型，其他人看到的是落子结果和理由。自建服务器等 150 秒还没收到这一步，就用大师电脑代下。大师电脑在自建服务器上由服务器计算，在 Claude 发布的页面里由房主的浏览器计算。

**在 Claude 发布的页面里**：页面不能访问外部网络，所以 DeepSeek、Jev 等接口用不了；可以在设置里选「本页面自带的 Claude」，使用你自己的 Claude 额度，第一次调用时页面会请你确认。

## 项目结构

```
index.html        页面结构
css/style.css     样式（默认浅色，可选深色主题；窄屏布局）
js/pieces.js      方块 21 块、三角块 22 块、宝石阵 18 块、立方体 12 块、三棱柱 19 块及其旋转 / 翻转
js/engine.js      规则引擎：方格 / 三角格 / 宝石阵六边形格 / 立方体 / 三棱柱拓扑、重力落子、合法性检查、走法生成、轮转、计分、重放
js/ai.js          电脑玩家
js/llm.js         大模型电脑：挑选候选、提示词、调用 OpenAI 兼容接口 / Jev / 页面自带的 Claude、解析回答
js/view3d.js      立体与三棱柱模式的绘制（Canvas 2D 正交投影，无依赖）与拾取
js/online.js      联机房间逻辑（服务器与浏览器共用）：入座、开局、校验棋步、托管、换房主
js/net.js         联机传输层：自建服务器 / Claude 页面共享存储
js/record.js      对局记录：生成、校验、导出（含可读流程）与回放用的局面
js/i18n.js        多语言：语言列表、按浏览器语言自动选择、取词（占位符、复数、退回英文）
js/i18n/*.js      各语言词典（en.js 为全部词条的清单）
js/app.js         界面与交互
server.js         联机服务器（Node.js，无依赖）
tests/            规则引擎、电脑、大模型电脑、房间逻辑、服务器、对局记录与多语言词典的测试
```

`pieces.js`、`engine.js`、`ai.js`、`llm.js`、`online.js`、`record.js`、`i18n.js` 不依赖 DOM，可以在 Node 中直接使用。

## 测试

```bash
npm test
```

测试会在方格、三角格、宝石阵、立方体和三棱柱棋盘上把走法生成结果与暴力枚举逐一比对，跑完整的随机对局检查终局与重放的一致性，校验房间操作的权限，并启动服务器让两个客户端加两个电脑完整打完一局。大模型电脑用假的接口测试候选范围、提示词、回答解析、DeepSeek 关闭思考与重试、Jev（官方与 OpenRouter）、出错与取消、服务器转发，以及联机时由房主代为落子、超时由服务器代下。对局记录测试保存、导出、再导入后重放得到同一局面，并检查导入的文件被篡改时（名字、颜色、模式、座位、动作）的处理。多语言测试检查自动选择语言的规则，以及每种语言的词条、占位符、HTML 标签和复数形式是否齐全，代码和页面里用到的词条是否都有。
